# 전수 점검 체크리스트 (AUDIT_CHECKLIST)

> 2026-10-28. 장애(FAULT_MATRIX)만 보던 점검을 표준 체크리스트 전체로 넓힌다. 완전성의 정의: **이 문서의 모든 항목을 영역마다 '해당 없음(이유) / 문제 없음(근거) / 문제 있음(발견)' 중 하나로 표시**한다. 이 목록 밖의 문제는 이 점검이 보장하지 않는다. 출처 기준: Google SRE 출시 점검, OWASP ASVS/Top 10, 12-factor, CIS Docker/Compose 권고, PostgreSQL 운영 관행, 의료정보 일반 원칙(최소 수집·보존·비식별·접근 기록).

## 항목 (각 항목마다 판정과 근거 파일:줄)

**A. 신뢰성** A1 모든 외부 호출에 연결·읽기 timeout. A2 재시도는 멱등한 호출에만, 백오프+지터, 상한. A3 장애 중 부분 쓰기·반쯤 쓴 상태가 남지 않음(트랜잭션/원자적 교체). A4 우아한 종료(진행 중 요청 마무리, 새 요청 거부). A5 재시작·복구 후 사람 개입 없이 정상화. A6 큐·캐시·로그·테이블 무한 증가 없음(상한/정리). A7 동시성: 경쟁 상태, 락 순서, 데드락, 이중 처리. A8 /healthz·/readyz 의미. A9 자원 한도(메모리·스레드·연결·파일 핸들·디스크).

**B. 보안** B1 인증: 모든 비공개 경로가 인증을 요구하는가(기본 거부). B2 인가: 역할 분리, 수평 권한 상승(다른 세션·다른 사용자 데이터 접근). B3 비밀: 파일/주입 방식, 로그·오류·/readyz·이미지·git에 비밀이 없음, 회전 가능. B4 입력 검증: 크기 상한, 타입·열거값, 경로 조작, 파일 이름, 정규식 폭주(ReDoS), 역직렬화. B5 인젝션: SQL(파라미터화), 명령, 템플릿, 프롬프트 인젝션(환자 발화가 모델 지시를 바꾸는가), 로그 인젝션. B6 SSRF·외부 URL 사용. B7 웹: XSS/CSP, CSRF, 쿠키 속성, CORS, 보안 헤더, 클릭재킹, 서비스 워커 범위. B8 전송: TLS 요구/종료 지점, 내부 평문 구간의 노출 범위. B9 의존성: 알려진 취약점(pip-audit/npm audit/컨테이너 이미지), 핀·락, 공급망(태그 불변성, digest 고정). B10 속도 제한·남용 방지(로그인 시도, 세션 시작 남발). B11 오류 응답이 내부 정보를 노출하지 않음. B12 토큰 수명·범위·최소 권한(DB 계정, 서비스 토큰).

**C. 데이터·개인정보** C1 어떤 개인(건강)정보가 어디에 저장·전송·기록되는지 목록(발화 원문, 세션, 참조값 subject_ref, 직원 ID, 로그). C2 최소 수집(필요 없는 값 저장 안 함). C3 보존 기간·삭제 경로가 있고 기본값이 안전한가(기본 무기한이면 지적). C4 비식별: 로그·Trace·실패 사례·모델 학습 환류에서 식별정보 제거. C5 저장 시 암호화/볼륨 권한, 전송 시 암호화. C6 접근 기록(누가 무엇을 열람/변경했나, 행위자 기록 위조 불가). C7 백업·복원: 주기, 복원 시험, 백업 파일 권한·암호화, 보존. C8 DB 계정 최소 권한·서비스별 분리. C9 마이그레이션·스키마 변경 순서와 되돌리기. C10 데이터 정합성: 외래키/유일성/CHECK 제약, 시간대·UTC, 한글 유니코드 정규화.

**D. 정확성·계약** D1 공개 API가 boundary-contracts와 일치(필드·열거값·오류 코드·상태 코드). D2 상태 기계의 불가능한 전이 방어. D3 멱등키·중복 요청. D4 시간·시계(만료, 타임존, 시계 어긋남). D5 인코딩·크기(8MiB, 긴 한글, 이모지, null 문자). D6 값 지어내기 금지(모델 출력 검증, UNKNOWN_SLOT 등). D7 문서와 코드의 일치.

**E. 운영성** E1 구조화 로그(상관 ID, 수준, 비밀·PHI 제외). E2 메트릭·지표 노출과 경보 기준. E3 설정은 환경으로, 기본값 안전, 잘못된 설정은 시작 거부. E4 런북: 장애별 대응 절차. E5 감시 대상과 알림 경로. E6 용량 계획 근거(측정 유무). E7 시작 순서·의존 준비 대기. E8 시간 불변식(timeout 체인)이 문서에 있고 코드와 같음.

**F. 배포·이미지** F1 비root, 읽기 전용 루트 파일시스템 가능성, 불필요한 권한(capabilities, privileged, docker.sock), 포트 노출 최소(호스트 바인딩은 127.0.0.1/gateway만). F2 이미지 핀(digest)·재현 가능 빌드·SBOM/취약점 스캔. F3 compose: 자원 한도, restart 정책, 네트워크 분리(이미 per-service DB 네트워크), 볼륨 권한. F4 릴리스 되돌리기와 업그레이드 순서(영역 버전 정렬). F5 비밀 파일 권한(0600/0400), 비밀이 compose 환경에 없음. F6 레지스트리·CI 신뢰 경계.

**G. 성능·용량** G1 측정된 처리량·지연과 한계 문서화(측정 조건 포함). G2 N+1 쿼리, 누락 인덱스, 풀 부재, 락 보유 시간. G3 큰 입력에서 CPU/메모리 폭주.

**H. 시험 품질** H1 핵심 경로(환자 턴, 승인/활성화/롤백, 알림)가 실제 구성요소로 시험됨(모킹이 실제 동작을 가리지 않음). H2 간헐 실패(실제 타이머, 고정 포트, 순서 의존). H3 건너뛰는 시험의 사유와 대체 수단. H4 부정 시험(거부되어야 하는 입력·권한). H5 시험이 환경(디스크, 네트워크, 시계, 설치 방식)에 의존하지 않음.

**I. 도메인·안전** I1 환자 안전과 닿는 결정(직원 호출, 위험 신호, 대체 문구, 재질문 상한)이 코드에 임의로 박혀 있지 않고 사용자 결정 표시가 되어 있음. I2 환자에게 가는 문구의 출처(임상 검토 필요 표시). I3 실패 시 환자에게 무엇이 보이는가(조용히 비거나 잘못된 안내가 없음).

**J. 근거('왜') 문서화 (D89)** J1 영역의 구조 선택마다 ADR이 있고 '왜'·표준·검토한 대안·결과가 적혀 있다. J2 모든 timeout·상한·보존 기간·기본값에 근거(측정/표준/제약 중 무엇인지, 측정 안 했으면 안 했다고)가 코드 상수 옆이나 ADR에 있다. J3 저장소·프로토콜·서버 구현·인증·동시성 모델의 선택 이유가 문서에 있다(예: SQLite를 왜 쓰는지, 운영은 왜 PostgreSQL인지). J4 비자명한 코드에 '왜' 주석. J5 ADR과 코드·설정이 일치하고 대체된 결정은 `Supersedes`로 이어진다. J6 영역 README가 ADR 목록을 링크한다.

## 판정 표기
각 항목: `OK(근거)`, `문제(심각도 H/M/L, 근거, 제안 수정, 자율 수정 가능 여부 / 사용자 결정 필요)`, `해당 없음(이유)`, `확인 못 함(이유)`. '확인 못 함'도 정직한 판정이다. 근거 없이 OK를 쓰지 않는다.
