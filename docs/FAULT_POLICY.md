# 장애 대응 정책 (FAULT_POLICY)

> 헤드가 표준 관행으로 정한 기대 동작이다(2026-10-28). `FAULT_MATRIX.md`의 '?'(미정의) 칸을 이 원칙으로 채운다. 환자 안전·도메인 판단이 들어가는 항목은 맨 아래 '사용자 결정'에 따로 둔다. 이 문서에 쓴 값은 구현·시험으로 확인되기 전에는 '정한 것'이지 '확인한 것'이 아니다.

## 원칙

1. **턴은 확정되거나 확정되지 않는다.** 장애 중 환자 턴은 부분 저장되지 않는다. 확정되지 못하면 `NOT_COMMITTED`로 끝나고 같은 `turn_id` 재전송이 안전하다.
2. **같은 `turn_id`는 멱등이다.** 이미 확정됐으면 저장된 결과를 그대로 돌려준다. 처리 중이면 새로 시작하지 않고 `409 TURN_IN_PROGRESS`(+`Retry-After`)를 준다. 두 번 처리되어 값이 두 번 저장되는 일이 없다.
3. **서버 턴에는 총 마감 시간이 있다.** 서버는 키오스크의 대기 한도보다 짧은 총 마감(기본 9초, D119) 안에 확정하거나 `NOT_COMMITTED`로 끝낸다. 호출별 timeout의 합이 아니라 요청을 받은 때부터 턴 전체에 거는 상한이다. 불변식: 키오스크 대기 10초 > gateway 9.5초(연결 1 + 응답 헤더 8.5) > 서버 마감. 6초는 DB 장애 최악 경로 측정값 5.0초(pause)에서 정했다(2026-10-28, 이 PC 1회 측정).
4. **의존이 응답하지 않을 때 무한히 기다리지 않는다.** DB는 `connect_timeout`과 `statement_timeout`을 가진다. 이웃 서비스 호출은 읽기 timeout을 가진다. 값은 설정으로 두고 기본값과 근거를 영역 문서에 적는다.
5. **`/healthz`는 살아 있음, `/readyz`는 의존 준비됨.** 의존이 죽으면 `/readyz`는 2초 안에 503과 원인(접속 정보 없음)을 준다. `/healthz`는 의존과 무관하게 200이다. gateway의 `/readyz`는 정적 200이 아니라 환자 경로의 survey-service `/readyz`를 반영한다.
6. **gateway는 상류 장애를 구분해 알린다.** 상류 연결 거부·재시작은 `503`, 상류 시간 초과는 `504`, 모두 JSON 본문 `{"code": "UPSTREAM_UNAVAILABLE", ...}`와 `Retry-After`를 가진다. 본문에 내부 주소·접속 정보를 넣지 않는다.
7. **키오스크는 일시 장애를 재시도하고, 예산이 끝나면 직원을 부른다.** 502·503·504·네트워크 오류·429는 같은 `turn_id`로 지수 백오프(지터 포함) 재시도한다. 총 재시도 예산(기본 약 20초)을 넘으면 직원 호출 화면으로 간다. 4xx(429 제외)는 재시도하지 않는다. 모든 키오스크가 동시에 같은 시각에 재시도하지 않도록 지터를 둔다.
8. **알림과 확정은 분리하지 않는다고 가정하지 않는다.** 쓰기 확정이 실패한 턴의 위험 신호 처리는 아래 '사용자 결정'이다.
9. **인증 실패는 재시도로 해결되지 않는다.** 401/403은 즉시 실패하고, 호출자는 이를 `/readyz`·경보에서 보이게 한다(조용히 버리지 않는다). Trace처럼 비동기 전송에서 인증 실패로 DEAD가 된 건수는 `/readyz` 또는 상태 API에 건수로 드러난다.
10. **깨진 응답은 신뢰하지 않는다.** 상대 응답이 스키마·형식에 맞지 않으면 성공으로 취급하지 않고(값을 지어내지 않는다) 5xx 계열과 같이 실패로 처리한다.
11. **분리(F8)는 중지(F1)·멈춤(F2)과 같은 규칙을 따른다.** 연결할 수 없으면 F1, 연결은 되나 응답이 없으면 F2로 분류하고 그 칸의 규칙을 적용한다.
12. **재시작은 복구 후 이전 확정 데이터를 보존한다.** 의존이 돌아오면 사람 개입 없이 `/readyz`가 200이 된다. 확정되지 않은 비동기 전송(outbox 등)은 복구 후 재전송된다.
13. **디스크 가득·자원 한도는 경보 대상이다.** 한도 근처에서 경보를 내고, 가득 차면 쓰기를 거부(503)하며 기존 데이터를 깨뜨리지 않는다.
14. **감시는 서버 밖에서 gateway `/readyz`를 본다.** 스케줄러/잡 실패는 상태 파일 또는 API로 드러나고 점검 스크립트가 읽는다.

## 사용자 결정이 필요한 항목 (환자 안전·운영)

- 쓰기 확정이 실패한 턴(예: DB 중지 중)에서 환자 발화에 위험 신호가 있을 때, 확정 없이도 직원 알림을 보낼지. (`survey-service/docs/boundary.md` 6절이 도메인 소유자 확인 대기로 적고 있음)
- 자동 롤백 기준(`rollback: null`을 어떤 기준으로 채울지).
- 저자가 운영 구성에서 문항을 올리는 경로(E2)를 열지 말지.
- 키오스크 재시도 총 예산(기본 약 24초)과 서버 턴 총 마감(기본 9초, D119)이 임상 현장 흐름에 맞는지.
