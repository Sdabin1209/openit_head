# 0004. 서비스가 모델 출력을 검증하고, 모델이 값을 지어내지 못하게 한다

- 상태: 수용(값 타당성 검증의 위치는 일부 미확인)
- 결정 기록: [D36](../DECISIONS.md)(v1, D75가 대체), [D48](../DECISIONS.md), [D75](../DECISIONS.md), [D82, D83](../DECISIONS.md)
- 관련 ADR: 0003, `turn-engine` ADR 0002·0004, `boundary-contracts` ADR 0006

## 맥락

모델은 가끔 틀리거나 값을 지어낼 수 있다. 의료 문진 기록에 틀린 값이 들어가는 것은 다시 묻는 것보다 위험하다(D75-1). v1에서는 파서가 형식을 어기면 정해진 대체 출력을 돌려줬다(D36).

## 결정

검증을 세 층으로 쌓고 어느 층에서든 실패하면 값을 만들지 않는다.

1. 제약 디코딩(vLLM+xgrammar): 형식을 생성 때 강제한다. 지키지 못하는 키워드는 완화하거나 변형한다(D82, D83).
2. 형식 사후 검증: model-runtime이 `ActionExtraction` 스키마로 검증한다.
3. 의미 사후 검증: turn-engine의 `validate_extraction`이 `targets`, `next_item`, 건너뛰기 순서, `save` 규칙을 확인하고 survey-service가 호출한다.
4. 실패 처리(D75-1): 서버는 값을 지어내지 않고 503 `UNAVAILABLE`(`details.reason=OUTPUT_INVALID`)을 낸다. survey-service는 한 번 재시도하고, 그래도 안 되면 그 턴을 실패 신호(`turn_failure_signal`)로 처리하며 세션 상태를 바꾸지 않는다. 대체 출력을 만들지 않는다.
5. 값의 타당성(칸별 타입·열거·범위 등)은 서비스가 문진 스키마로 한다. 단 현재 어디까지 하는지는 확인하지 못했다(`turn-engine` 점검 TE-1 열림).

## 왜

- 의료 기록에 틀린 값이 들어가는 비용 > 다시 묻는 비용. 의료 triage에서 놓침 비용을 거짓 경보 비용보다 크게 보는 관행과 같은 방향이다(D88 U1에서도 같은 원칙).
- 제약 디코딩만으로는 부족하다: vLLM 구조화 출력이 `allOf`·`if/then`·`not`을 조용히 무시한다(D48). 그래서 조건 규칙을 사후 검증이 맡는다.
- 층을 나눈 이유: 형식은 model-runtime(모델 서버)이, 의미는 순수 함수 라이브러리가, 값 타당성은 문진 스키마 소유자가 맡아 책임이 한 곳에만 있다(소유 원칙, ADR 0001).
- v1의 "대체 출력으로 고쳐 쓰기"(D36)를 v2에서 바꾼 이유: 고쳐 쓴 값이 환자가 말한 값이 아닐 수 있다. 값을 지어내지 않는 쪽이 안전하다. 이 대체는 D75에 명시된 방향이다.

## 검토한 대안과 버리는 이유

| 대안 | 버리는 이유 |
|---|---|
| 모델을 신뢰하고 검증 생략 | 모델은 가끔 틀린다는 전제(D75-1) |
| 규칙 위반을 서버가 정정 | 환자가 말하지 않은 값이 저장될 수 있다. D36의 대체 출력 방식은 v2에서 폐기 방향 |
| 위반 시 세션 중단 | 근거 기록: 직접 비교한 문서는 없다. D75-1은 턴 실패 신호로 처리하고 세션 상태는 유지한다고만 정했다 |
| 제약 디코딩만 사용 | 조건 키워드를 못 지킨다(D48) |

## 결과

- 얻는 것: 틀린 값이 기록되지 않는다. 위반이 코드와 위치로 기록된다(값은 로그에 싣지 않는다).
- 감수하는 것: 재질문이 늘어 환자 경험이 나빠질 수 있다. 재질문 상한과 직원 호출 기준은 임시값이다(D88 U10, OPEN_GAPS). `OUTPUT_INVALID` 비율은 측정하지 못했다(GPU 실측 전, U04·H1). 모델 B(응답)의 내용 검사는 비어 있지 않음만 확인하고 숫자·내용 검사가 없다(점검 MR-2, G05 열림).

## 되돌리는 조건

사후 검증이 정상 출력을 반복해 거부(오탐)한다는 운영 지표가 쌓이면 규칙을 조정한다. 규칙 확장·완화는 turn-engine MINOR 변경이다.
