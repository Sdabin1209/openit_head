# 0005. 운영 저장소는 PostgreSQL, SQLite는 개발·시험용

- 상태: 수용(D85가 D50을 대체). 선택의 '왜' 문장은 D85에 없다 (아래 참고)
- 결정 기록: [D50](../DECISIONS.md)(SQLite로 시작), [D85](../DECISIONS.md)(6항: PostgreSQL 사용)
- 관련 ADR: 0001, 0002

## 맥락

D50(2026-10-15 무렵)은 저장소를 SQLite로 하고 소유 서비스의 볼륨 하나에만 쓰며, 데이터가 커지거나 동시성이 문제가 되면 별도 결정으로 다시 연다고 했다. 2026-10-27 사용자 지시로 D85가 결함 목록의 결정을 닫으며 "DB 서버(PostgreSQL)를 쓴다"고 정했다. 보존 기간은 기본 null이고 설정으로만 준다. 이 결정 문장에는 PostgreSQL을 고른 이유가 적혀 있지 않다.

## 결정

- 운영 저장소는 PostgreSQL(DB 서버)이다. 각 서비스가 자기 영역의 DB/스키마를 소유하고 이웃은 HTTP로만 읽는다(D49, D50 유지).
- SQLite는 개발·시험용이다. 같은 SQL로 SQLite와 PostgreSQL을 모두 지원하고(survey-service 점검에서 확인: "PG 같은 SQL"), 개발·단위 시험은 서버 없이 SQLite로 돌린다.
- 한 영역의 소유 규칙은 그대로다: 쓰기는 소유 서비스만, 읽기 전용 계정은 이웃에게(`CONVENTIONS.md` 6절).

## 왜

D85에 이유가 없으므로 아래는 D50, 규약, 점검 문서에서 읽을 수 있는 사실과 추정을 구분해 적는다.

확인된 사실:
- D50의 재검토 조건("데이터가 커지거나 동시성이 문제가 되면")과 D85의 병행 결정: 세션 락, `turn_id` 멱등, 낙관적 revision 검사가 있고 PG는 `FOR UPDATE`를 쓴다(survey-service 점검 A7). 동시 접근과 트랜잭션 격리를 서버가 보장하는 쪽이 강하다.
- 규약은 "다른 영역에는 읽기 전용 DB 계정만 준다"고 한다(`CONVENTIONS.md` 6절). 파일 기반 SQLite는 계정 분리가 안 된다(D50이 "DB 서버와 DB 계정 분리는 두지 않는다"고 했던 이유가 바로 이것이었고 D85가 뒤집었다).
- WAL 모드 SQLite가 읽기 전용 마운트에서 열리지 않는 문제가 있었다(D50).
- 환자 발화·세션 문서가 평문 JSON으로 저장된다(survey-service 점검 C5). 운영 DB 서버에서 접근 통제·백업·암호화를 표준 도구로 다루는 편이 파일 권한에 맡기는 것보다 낫다는 판단은 추정이다.
- 백업은 서버 밖 대상 필수, 암호화 표준 도구, 정기 복원 시험(D88 U6)이 정해졌다. DB 서버가 있으면 표준 백업 도구를 쓸 수 있다.

SQLite를 개발·시험용으로 남긴 이유:
- 개발은 컨테이너 밖에서 하고 이웃은 메모리 구현으로 대신하며 혼자 시험할 수 있어야 한다(`shared/CLAUDE.root.md`, D22). 서버 없이 도는 DB가 이 규칙에 맞다.
- 이 이유는 기록된 규칙에서 읽은 것이며 SQLite를 개발용으로 남기는 것을 직접 논의한 기록은 찾지 못했다.

## 검토한 대안과 버리는 이유

| 대안 | 버리는 이유 |
|---|---|
| SQLite를 운영에도 유지(D50) | 동시성·계정 분리·백업 표준 도구 면에서 D85가 뒤집었다. 구체 계기는 기록되지 않았다 |
| 다른 DB(MySQL, 문서형 DB 등) | 근거 기록 없음. 비교한 문서를 찾지 못했다 |
| 서비스마다 DB 서버를 하나씩 | 단일 서버 전제(ADR 0002)에서 서버 수만 늘어난다. 같은 DB 서버 안의 영역별 소유로 가는 것으로 읽히나 확정 기록은 없다 |

## 결과

- 얻는 것: 서버 재시작 복구 시험 통과(OPEN_GAPS U17: PG 컨테이너 재시작 후 4개 서비스가 7초 안에 `/readyz` 200, 행 지문 보존).
- 감수하는 것: 운영 경로(PostgreSQL) 시험이 기본 실행에서 건너뛰어진다(`TEST_DATABASE_URL` 없음 시 survey-service 34건, ops-feedback 110건 등: 점검 H3). 두 DB 방언의 차이가 어긋날 위험이 있다. 보존 기간·자동 삭제 정책은 병원 몫이고 미정이다.

## 되돌리는 조건

단일 서버 한 대의 규모가 작고 DB 서버 운영 부담이 이점을 넘는다는 측정이 나오면 재검토한다. 그때는 SQLite 운영의 약점(위 사실 목록)을 어떻게 대체하는지가 먼저 정해져야 한다.
