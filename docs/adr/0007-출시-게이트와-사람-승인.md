# 0007. 출시 게이트: 기술 호환은 자동, 출고는 사람이 승인한다

- 상태: 수용
- 결정 기록: [D03](../DECISIONS.md), [D20](../DECISIONS.md), [D25](../DECISIONS.md), [D30](../DECISIONS.md), [D46](../DECISIONS.md), [D53](../DECISIONS.md), D58, D69~D71, [D80](../DECISIONS.md), [D88](../DECISIONS.md)(U7·U9·U11)
- 관련 ADR: 0004, 0009

## 맥락

모델 조합(기반 모델 + LoRA-A·B)을 서빙에 올리는 일은 환자 기록의 품질에 직결된다. 처음에는 지표 통과를 기준으로 하는 게이트 설계였다.

## 결정

- 평가는 임계치 없는 체계적 지표 보고서(`EvaluationReport`)를 낸다. 지표 통과가 곧 서빙이 아니다(D53).
- release-gate는 기술 호환(계약 호환, 문항-모델 호환, 보고서 형식, 버전 일치)만 자동으로 검사해 어긋나면 반려하고, 통과하면 `AWAITING_APPROVAL`에서 멈춘다.
- 출고는 AI 학습 담당자(`release-approver`)가 후보와 현재 활성 릴리스를 같은 지표끼리 맞댄 `ReviewReport`를 보고 `POST /v1/approvals`로 APPROVE/REJECT(반려는 사유 필수)한다. PASS `GateDecision`에는 `HUMAN_APPROVAL` 검사가 PASS여야 한다.
- 승인자는 개인으로 식별한다: `X-Openit-User`가 없으면 거부하고 접근 기록에 개인 ID를 남긴다(D88 U7). 임상 근거 승인은 저자≠검수자(4-eyes)를 기본으로 한다(D88 U9).
- 자동 롤백도 사람 승인을 유지한다(`auto_submit` 기본 false, 기준 값은 비워 둔다, D88 U11).
- 게이트의 버전 비교는 문자열 완전 일치다(D80). 임상 승인은 정확한 문항 세트 버전에 묶인다(D30).
- 판정과 승인 기록은 불변이고 새 레코드로 낸다(D25).

## 왜

- 사용자 결정(O11 닫음, D53): 출고는 사람이 정한다. 모델의 학습 품질과 통과 기준 자체가 미정(D38)이라 임계치 자동화는 근거가 없다.
- 의료 문진에서는 놓침 비용이 크다(D88 U1의 관행과 같은 방향). 사람이 최종 결정권을 갖되 필요한 비교 자료를 모아 보여 준다.
- 완전 일치(D80)의 이유: 이미지 전체가 같은 모델 코드로 학습·평가·서빙되어야 승인된 동작이 서빙 동작과 같다.
- 개인 식별(D88 U7): 누가 승인했는지 감사가 되어야 한다. 표준 관행(개별 계정, SSO/OIDC 지향, D85)을 따랐다.
- 4-eyes(D88 U9): 저자의 임상 근거를 같은 사람이 승인하지 못하게 해 자기 검토를 막는다. 표준 통제 관행이다.

## 검토한 대안과 버리는 이유

| 대안 | 버리는 이유 |
|---|---|
| 지표 임계치 자동 출고 | D53 사용자 결정. 통과 기준(O11)이 미정이었다 |
| 승인자 이름을 본문에 적게 함 | D88에서 `X-Openit-User`로 바꿨다. 조작 가능한 본문 값은 신원이 아니다. 이전 동작과 달라 소비 영역 호출 경로를 맞춰야 했다(boundary-contracts CHANGELOG) |
| 별도 임상 검수자 | D30: 문항을 올리는 사람이 의료인이므로 저자 확인을 임상 승인으로 했으나, D88 U9가 4-eyes 기본으로 강화했다(두 결정이 이어진다. D30의 "별도 검수자를 두지 않음"은 D88 U9로 보완). 정확한 대체 관계는 DECISIONS에 명시되지 않았다 |

## 결과

- 얻는 것: 승인된 조합만 서빙한다. 롤백 경로가 있다(`RollbackRequest`, 사람 승인 유지).
- 감수하는 것: 사람이 병목이다. 승인 화면과 검토 UI가 필요하다(admin-console, D68). 판단 기준 값(롤백 기준 등)은 비어 있어 병원 정책이 필요하다.

## 되돌리는 조건

통과 기준(O11)이 정해지고 운영 데이터가 쌓이면 일부 변경(예: 문구만 바뀐 PATCH)의 자동 출고를 검토할 수 있다. 환자 안전과 닿는 결정이므로 사용자 결정이 필요하다.
