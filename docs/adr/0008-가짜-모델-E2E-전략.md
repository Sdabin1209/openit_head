# 0008. 모델 성능과 파이프라인을 분리해 가짜 모델로 E2E를 돈다

- 상태: 수용. 실제 GPU 추론 E2E는 열림
- 결정 기록: [D38](../DECISIONS.md), [D61](../DECISIONS.md), [D67](../DECISIONS.md), [D72](../DECISIONS.md), [D81](../DECISIONS.md)
- 상세: [E2E.md](../E2E.md), 결과는 `deploy/docs/E2E_RESULTS.md`(이 ADR에 수치를 복사하지 않는다)

## 맥락

사용자의 목표는 실제로 구동 가능한 파이프라인을 완성하는 것이다. 모델을 직접 학습해 성능을 확인하는 것이 아니다(D38, D61). 학습/평가 서버(GPU)는 제한적이고 개발 PC에는 큰 GPU가 없다(gpu-dev 12GB).

## 결정

- E2E는 "각 단계가 다음 단계의 입력을 만들고 순환이 닫히는지"만 본다. 품질은 보지 않는다(E2E.md). 합격 조건은 1~9단계가 사람 손 없이 순서대로 실행되고 모든 레코드가 스키마·해시 검증을 통과하는 것이다.
- 추론 서버는 CPU/fake 변형으로 E2E에 쓰고, v2 extract·respond 경로로도 가짜 모델 E2E가 돈다(architecture.md).
- 추론 서버는 위치에 독립이다. 어디에 두든 기능 차이가 없고 호출자는 주소·토큰만 안다(D72). 그래서 가짜와 실제를 서버 교체만으로 바꿀 수 있다.
- 실제 LLM 데모는 별도(`demo.sh up --llm`)이고 gpu-dev의 Qwen3-1.7B까지 확인됐다(D81). 24GB급 실측은 열려 있다(H1).
- 큰 모델을 여러 개 내려받지 않고 기반 모델 후보 비교는 중단한다(D61).

## 왜

- 사용자 지시(D38, D61): 남는 일이 모델 성능 향상뿐이어야 하고, 그 전에 구조가 닫혀야 한다. 성능과 구조를 분리하면 GPU 없이도 계약·멱등·롤백·승인 흐름을 검증한다.
- 가짜 모델로 찾은 문제가 실제로 있었다: v1 시기 E2E에서 영역끼리 이어지지 않는 문제가 발견되어 D49(HTTP 경계)가 나왔다(D52).
- E2E를 단계별로 나눠 하나씩 고치는 개선(D67)도 이 전략의 일부다. 한 번에 처음부터 끝까지 도는 구조는 일부만 고쳐도 전체를 다시 돌려야 했다.

## 검토한 대안과 버리는 이유

| 대안 | 버리는 이유 |
|---|---|
| 실제 모델이 있어야 E2E | GPU 의존. 성능 시행착오와 구조 검증이 섞인다 |
| 단위 시험만 | 영역끼리 이어지는지 알 수 없다(D49의 계기) |
| E2E를 사람이 수동 | D38·D67: 사람 손 없이 도는 것이 합격 조건 |

## 결과

- 얻는 것: 한 PC에서 전체 모드 E2E가 가능하다(결과 수치는 `deploy/docs/E2E_RESULTS.md`).
- 감수하는 것(확인된 한계): 가짜 모델은 모델 품질, 제약 디코딩의 실제 거동(U04), 지연·용량(H1)을 검증하지 않는다. "E2E 통과"는 한 환경의 결과이며 두 번째 환경 확인이 아니다(사용자 피드백 규칙). `E2E_GPU=1`은 미검증이다.

## 되돌리는 조건

실제 GPU에서 한 턴 통과(OPEN_GAPS H2)가 확인되면 가짜 모델 E2E는 계속 기본 시험으로 두고 실제 모델 E2E를 추가한다(대체가 아니라 병행).
