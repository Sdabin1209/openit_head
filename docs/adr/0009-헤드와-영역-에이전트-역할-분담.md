# 0009. 헤드 에이전트와 영역 에이전트의 역할 분담

- 상태: 수용
- 결정 기록: [D09](../DECISIONS.md), [D19](../DECISIONS.md), [D21](../DECISIONS.md), [D23](../DECISIONS.md), [D37](../DECISIONS.md), [D41](../DECISIONS.md), [D60~D67](../DECISIONS.md)(작업 단위), [D78](../DECISIONS.md)(판단 위임), [D89](../DECISIONS.md)
- 규칙 원문: `shared/CLAUDE.root.md`, `head/CLAUDE.md`

## 맥락

사용자는 영역마다 에이전트 하나를 붙여 설계·구현(바이브코딩)시키고, 그것을 합쳐 올리길 원한다. 에이전트는 이전 세션 기억이 없다. 결정은 사용자가 직접 내리고 에이전트는 권고한다.

## 결정

- 헤드: 영역 사이 경계(계약, 수용 기준), 공통 규약, 결정 기록, 영역 브리프, 영향 정리와 병합·검증을 맡는다. 영역 내부 설계와 구현을 정하지 않고 영역 코드를 수정하지 않는다.
- 영역 에이전트: 자기 리포지토리 안에서만 일한다. 내부 설계·구현·시험, 자기 영역 문서(자기 영역의 사실만)를 맡는다. 계약이나 문진 스키마의 부족은 `docs/change-requests/`에 변경 요청으로 넘긴다.
- 문진 스키마는 survey-service가 소유한다(D19, D21, D23). boundary-contracts는 헤드가 소유하며 영역은 수정하지 않는다.
- push는 헤드가 허락한다(시험 결과와 커밋 작성자 확인, 강제 push 금지, D41). 커밋은 작업 단위마다 한다(D37).
- 작업은 짧은 단위로 쪼개 맡기고 단계마다 확인한다(D67). 사용자 몫의 결정(운영 정책, 영역의 존치, 환자 안전과 닿는 도메인 결정, 비용·외부 공개)만 묻고 나머지는 헤드가 판단한다(D78 위임, 피드백 규칙).
- 읽지 못한 것을 읽은 것처럼 쓰지 않는다. 일부러 비운 것은 `OPEN_GAPS.md`에 기록하고 완료 선언 전에 확인한다.

## 왜

- 컨텍스트가 매번 새로 시작되므로 맥락은 리포지토리 문서에 있어야 하고, 각 에이전트가 읽는 범위를 좁게 두어야 다른 영역을 망가뜨리지 않는다.
- 한 사실을 아는 영역이 한 곳에서만 쓴다: 복사된 사실은 서로 다른 시점의 값으로 어긋난다(워크스페이스 규칙). 점검에서 시험 개수·버전 복사 어긋남이 반복 발견되었다(예: MR-15).
- 헤드가 push를 허락하고 검증하는 이유: 영역 에이전트의 자체 보고만으로 완료를 믿지 않기 위해서다(수용 테스트와 계약 검증 통과 전에는 완료라 말하지 않는다). 사용자가 헤드에게 위임했다(D41).
- 계약을 헤드가 소유하는 이유: 영역 어느 한쪽이 계약을 고치면 이웃이 조용히 깨진다(D19). 변경 요청을 거치면 영향 정리와 버전 부여가 한 곳에서 이루어진다.
- 짧은 작업 단위의 이유: 긴 작업을 에이전트에 맡기면 완료 확인 없이 방치되는 일이 있었다는 사용자 피드백이 있다(메모리 피드백 규칙; 이 ADR 작성 시 원문 재확인은 안 했다).

## 검토한 대안과 버리는 이유

| 대안 | 버리는 이유 |
|---|---|
| 에이전트 하나가 전체를 구현 | 컨텍스트 한계와 책임 경계 불명확. 근거 기록: 직접 비교한 문서는 찾지 못했다 |
| 영역 에이전트가 서로 직접 수정/요청 | 소유 원칙 위반. 헤드를 거치는 변경 요청으로 대체 |
| 영역이 자체 push | D41: 헤드가 시험 결과와 작성자를 확인 |
| 모든 결정을 사용자에게 질문 | 사용자 요구: 사용자 몫만 묻는다(D78, 피드백) |

## 결과

- 얻는 것: 영역 에이전트 병렬 작업이 가능하고(독립 영역은 효율적이면 병렬 허용, 검증·병합은 헤드), 변경 흐름이 추적된다.
- 감수하는 것: 헤드가 병목이다(검증·병합·push 허락). 문서가 많아 어긋난다. 영역 에이전트의 보고는 한 환경에서의 결과이며 헤드가 두 번째 환경에서 확인해야 한다. D89(이 ADR 포함)처럼 모든 영역이 ADR을 쓰는 일은 헤드가 영역 에이전트에 위임해 일관성을 점검한다.

## 되돌리는 조건

팀이 커져 헤드 역할을 사람에게 나눌 때, 또는 영역이 합쳐질 때(ADR 0001의 되돌리는 조건) 이 분담을 갱신한다.
