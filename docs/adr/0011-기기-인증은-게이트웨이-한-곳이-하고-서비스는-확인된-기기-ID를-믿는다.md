# 0011. 기기 인증은 게이트웨이 한 곳이 하고 서비스는 확인된 기기 ID를 믿는다

- 상태: **ADR 0012로 대체됨(2026-10-29)**. 표준(기기 인증서 mTLS)을 기본 채택해 이 문서의 '게이트웨이가 기기 토큰을 확인하고 기기 ID 헤더를 붙인다'는 구조만 이어받았다. 아래는 이력으로 남긴다
- 관련: 구조 규칙 6개와 R7(D104), D85(F절 기기 토큰), D88(U8), `PUBLIC_API.md` 키오스크 인증, ADR 0010

## 맥락

- 키오스크는 사람이 로그인하지 않는 단말이라 기기별 토큰으로 인증한다(D85). 토큰이 없으면 서버 주소에 닿는 누구나 세션을 만들고 읽을 수 있고, 기기별 폐기도 못 한다.
- 지금은 인증을 **두 곳**이 한다: 게이트웨이가 기기 토큰 목록(`gateway-devices.caddy`)과 대조하고, 받은 토큰을 그대로 넘기면 survey-service가 같은 토큰 표(`SURVEY_KIOSK_DEVICE_TOKENS_FILE`)로 다시 검증한다(`HTTP.md`·`PUBLIC_API.md`, deploy runbook 9-5절).
- 사람 계정(직원, 승인자, 저자)은 다른 방식이다: 게이트웨이가 인증하고 `X-Openit-User`만 붙여 넘기며 서비스는 그 값을 믿는다.
- 결과: 토큰 목록이 두 곳에 있고 `kiosk-add-device.sh`가 둘을 동기화한다. 폐기는 게이트웨이에서 즉시 막히지만 survey-service 표는 survey 재시작 뒤에 바뀐다(runbook 9-5절).

## 결정 (제안)

1. 기기 인증은 **게이트웨이 한 곳**의 일이다. 입력은 `Authorization: Bearer <기기 토큰>`, 출력은 확인된 `device_id` 또는 401이다.
2. 게이트웨이는 클라이언트가 보낸 `X-Openit-Device`를 지우고, 인증에 성공하면 `X-Openit-Device: <device_id>`를 붙여 서비스에 넘긴다. 토큰 자체는 서비스에 넘기지 않는다. 사람 계정의 `X-Openit-User` 처리와 같은 방식이다.
3. survey-service는 기기 토큰 표를 갖지 않는다. `X-Openit-Device` 값을 믿고, 세션을 만든 기기 ID를 세션에 기록하고, 같은 기기 ID만 그 세션에 접근시킨다.
4. 기기 폐기는 게이트웨이의 기기 목록 한 곳에서 끝난다(재시작이나 reload 한 번).
5. 이 변경은 영역 간 스키마(I10의 키오스크 인증, `X-Openit-Device` 헤더 규칙)를 바꾸므로 헤드가 `PUBLIC_API.md`와 `HTTP.md`를 고친다.

## 왜

- 규칙 7: 인증된 값(기기 ID)은 한 번 보증되면 다른 컴포넌트가 믿고 쓴다. 두 곳 검증은 규칙 7과 어긋난다.
- 단일 정본: 토큰 목록이 한 곳이면 동기화 도구와 survey 재시작이 필요 없다.
- 일관성: 사람 계정 경로와 같은 패턴(`X-Openit-User`)이다.

## 검토한 대안과 버리는 이유

| 대안 | 버리는 이유 |
|---|---|
| 현행 유지(이중 검증) | 위 규칙 7 위반과 동기화·재시작 비용. 얻는 것은 게이트웨이를 우회한 직접 호출도 막는다는 점(심층 방어)인데, 서비스가 게이트웨이 뒤 내부 네트워크에만 있으면(ADR 0005) 우회 경로가 없다 |
| 토큰 없이 네트워크 격리만 | 환자 정보에 닿는 API를 주소 접근만으로 열게 된다. 위협 모델(누가 키오스크 서버에 닿을 수 있는가)을 비교한 기록이 없고 사용자 결정 사항이다 |
| 모든 기기가 같은 토큰을 공유 | 한 기기가 뚫리면 전체를 바꿔야 하고 기기별 폐기와 세션 소유 확인이 불가능하다(D85가 이미 버림) |

## 결과

- 얻는 것: 인증 컴포넌트가 하나, 토큰 목록 정본이 하나, 폐기가 즉시 한 곳에서 끝난다.
- 감수하는 것: 서비스가 게이트웨이를 신뢰한다(서비스를 게이트웨이 밖에서 직접 부를 수 있는 경로가 없어야 한다는 전제를 deploy의 네트워크 구성이 보증해야 한다). 이 전제는 이 PC에서 확인했다고 기록된 것(E2E 네트워크 도달 시험: 서비스가 호스트로 포트를 열지 않음)이 있으나 이 ADR 변경 뒤 다시 확인해야 한다. `X-Openit-Device` 규칙은 이 PC에서 구현·검증한 적이 없다(미측정).

## 되돌리는 조건

서비스를 게이트웨이 밖으로 직접 노출해야 하는 요구가 생기면 서비스 쪽 검증을 되살리는 안을 새 ADR로 비교한다.
