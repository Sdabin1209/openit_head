# 0012. 키오스크 기기 인증은 표준대로 기기 인증서(mTLS)와 네트워크 분리로 한다

- 상태: **기본 채택(2026-10-29)**. 사용자의 상시 지시("표준적인 방법을 먼저 생각한다")를 적용한 기본값이다. 사용자 이의가 있으면 바꾼다. 구현은 현재 E2E·데모 확인 뒤에 한다.
- 대체: ADR 0011(보류)과 D85(4)의 "기기별 토큰이 곧 자격"을 인증 수단만 바꿔 대체한다. D85의 목적(기기별 폐기, 세션을 만든 기기만 접근)은 유지한다.
- 관련: 구조 규칙 6개와 R7(D104), ADR 0001, ADR 0005

## 맥락

- 지금은 장기 보관 기기 토큰을 설정 파일(`/config.json`)이나 URL 조각으로 키오스크에 넣는다. 그 결과 (1) 토큰을 누가 기기에 넣는지 정해져 있지 않고, (2) 인증을 게이트웨이와 survey-service 두 곳이 하며, (3) 토큰 목록 동기화와 서비스 재시작이 필요하고, (4) 데모에서는 `/config.json`을 열어 주는 우회가 필요했다(deploy runbook 9절, 점검 보고서 KF-01).
- 이 조직 환경에서 고정 단말 인증의 일반적 표준은 네트워크 분리와 기기 인증서(mTLS, 802.1X EAP-TLS), 그리고 인증서와 설정을 기기에 넣는 주체로 기기 관리 시스템(MDM)이다. 장기 토큰을 파일에 붙이는 방식은 약한 쪽이다. 이는 일반 지식이며 이 저장소에서 검증한 것이 아니다.

## 결정

1. 키오스크 경로의 기기 인증은 **게이트웨이(Caddy)의 클라이언트 인증서 검증(mTLS)**이다. 입력은 TLS 클라이언트 인증서, 출력은 확인된 `device_id`(인증서 주체 이름) 또는 거부다.
2. 게이트웨이는 클라이언트가 보낸 `X-Openit-Device`를 지우고, 인증에 성공하면 확인된 `device_id`를 `X-Openit-Device`로 붙여 서비스에 넘긴다(사람 계정의 `X-Openit-User`와 같은 방식). 서비스는 이 값을 믿고 세션을 만든 기기 ID를 기록하며 같은 기기만 접근시킨다. 서비스에는 기기 토큰 표가 없다.
3. **이 프로젝트는 자격을 발급하거나 관리하지 않는다.** 인증서의 발급·갱신·폐기와 기기에 넣는 일은 조직의 PKI와 기기 관리 시스템(MDM)의 몫이다. 게이트웨이는 **신뢰할 CA 인증서(신뢰 기준점) 하나를 설정으로 받아** 그 CA가 발급한 인증서만 통과시킨다. 기기 허용·폐기 판단은 조직이 CA/CRL로 한다. 이 프로젝트는 시험·데모를 위해 일회용 CA와 기기 인증서를 만드는 도구만 제공하며, 운영에서 쓰지 않는다고 표시한다. 이전에 이 ADR이 'CA 발급 도구 제공'이라고 쓴 것은 자격 체계를 우리가 소유하는 오류여서 고쳤다.
4. 네트워크 분리를 함께 쓴다: 키오스크 서브넷에서만 게이트웨이의 키오스크 경로에 닿게 한다(배치 지침, 구현 아님).
5. 환자 쪽 자격은 기기가 아니라 방문이다: 접수 시스템이 넘기는 `subject_ref`로 세션이 환자에게 묶인다(현행 유지).
6. 영역 간 계약 변경(I10의 키오스크 인증, `X-Openit-Device` 규칙)은 헤드가 `PUBLIC_API.md`와 `HTTP.md`에 반영한다.

## 왜

- 표준: 고정 단말은 사용자 계정 대신 기기 자격으로 인증하며, 기기 인증서와 네트워크 분리가 일반적 방식이다.
- 규칙 7과 규칙 1: 인증 컴포넌트가 하나(게이트웨이)고 서비스는 확인된 기기 ID만 믿는다. 이웃 영역이 서로의 토큰 형식을 알 필요가 없다.
- 운영 비용: 토큰 파일 전달, 목록 동기화, 서비스 재시작, `/config.json` 우회, `NO_DEVICE_TOKEN` 화면이 사라진다.

## 검토한 대안과 버리는 이유

| 대안 | 버리는 이유 |
|---|---|
| 현행 기기별 장기 토큰(A) | 위 맥락의 비용 4가지. 표준에서 약한 방식 |
| 공유 키오스크 자격 하나(B) | 표준이 아니라 단순화일 뿐이고 기기별 폐기와 세션 소유 확인을 잃는다 |
| OAuth 2.0 기기 코드 흐름(RFC 8628) 등 짧은 수명 토큰 | 표준이지만 토큰 발급 서버(IdP)가 새로 필요하다. 인증서 방식이 게이트웨이만으로 되어 더 작다. IdP가 이미 있는 환경이면 이쪽도 표준이다 |
| 토큰 없이 네트워크 분리만 | 분리만으로는 같은 서브넷의 임의 기기를 막지 못한다. 위협 모델 비교 기록은 없다 |

## 결과

- 얻는 것: 인증 한 곳, 기기 목록 정본 하나, 폐기가 한 곳, 기기 쪽 파일 전달 공백이 MDM/OS 표준 절차로 넘어간다.
- 감수하는 것: 조직에 PKI/MDM이 있어야 한다(없는 환경은 일회용 CA 도구로 시험 구성만 가능). 키오스크 브라우저가 클라이언트 인증서를 쓸 수 있어야 한다. Caddy의 클라이언트 인증 설정이 이 구성에서 동작하는지, 발급 도구를 무엇으로 할지는 **확인하지 못했다(미검증)**. 데모 환경(이 PC)에서는 브라우저가 인증서를 제시하게 해야 하므로 데모 절차도 바뀐다. 성능과 handshake 비용은 측정하지 않았다.

## 되돌리는 조건

키오스크 브라우저가 클라이언트 인증서를 제시할 수 없는 기기를 써야 하면 짧은 수명 토큰(OAuth)이나 게이트웨이가 신뢰하는 네트워크 위치 기반으로 바꾸는 안을 새 ADR로 비교한다.
