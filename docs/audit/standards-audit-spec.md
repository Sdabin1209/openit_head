# 표준성·근거 전수 점검 기준서 (2026-10-29, D89)

사용자 지시(거듭된 상시 지시): 모든 요소는 **표준적인 방식**이어야 하고 **근거(이유)**가 있어야 한다. 표준이 있으면 그것을 따르고 근거에 그 표준을 적는다. 표준이 없으면 대안 비교로 정한다. "그냥", "관례상", "원래 그랬다"는 근거가 아니다. 앞선 구조 규칙 점검(R1~R7)은 이것을 보지 않았다.

## 점검 대상 = 선택을 담은 모든 요소 (영역마다 전수)
저장소 종류와 데이터 모델 모양, 프로토콜과 서버 구현, 인증·인가·자격(발급·보관·갱신·폐기 포함), 동시성 모델, timeout·재시도·한도의 값, 보존 기간, 비식별 방식, 식별자·해시·정규화·직렬화 형식, 파일·설정 형식, 스케줄링·잡 실행, 로깅·메트릭, 비밀 처리, 빌드·배포·이미지 방식, 의존 라이브러리의 핵심 선택, 시간·난수 처리.

## 요소마다 적을 것
1. **선택**: 무엇을 골랐나. `파일:줄`과 인용 2줄 이내.
2. **표준**: 이 선택이 따르는 이름 있는 표준·관행(RFC, NIST, OWASP, 12-factor, Postgres/HTTP/OAuth 등의 문서화된 관행)을 **정확한 이름으로** 적는다. 모르면 "표준 여부 확인 못 함"이라고 쓴다. 이름을 지어내거나 막연히 "업계 표준"이라 쓰지 않는다.
3. **근거 기록**: 이 선택의 이유가 어디에 적혀 있나(ADR 번호, D번호, 주석). 없으면 "근거 기록 없음".
4. **직접 만들었나, 가져다 썼나**: 이 영역이 표준 인프라·라이브러리가 제공하는 것을 직접 만들거나 운영하고 있지 않은가(자격 발급·관리, 스케줄러, 암호·비밀 관리, 인증서/PKI, 큐, 캐시, 해시 체인 등). 직접 만들었다면 **왜 가져다 쓰지 않았는지**의 근거가 있나.
5. **분류**: 
   - S = 표준을 따르고 근거도 있다
   - S- = 표준을 따르지만 근거 기록이 없다
   - N = 표준이 아니지만 근거(대안 비교)가 있다
   - N- = 표준이 아니고 근거도 없다
   - O = 가져다 써야 할 것을 직접 만들었다(재발명)
   - ? = 표준 여부를 확인하지 못했다
6. 값(숫자)은 **측정·표준·제약 중 무엇에서 나왔는지**와 "측정하지 않았다"를 구분해 적는다.

## 증거 규칙
- 모든 항목에 `파일:줄`. 읽지 못한 것은 읽지 못했다고 쓴다. 추측하지 않는다. 표준을 인용할 때는 그 표준이 정확히 무엇을 요구하는지 아는 것만 쓴다.
- 결과표: 요소, 분류, 표준 이름, 근거 위치, 증거 위치. 끝에 N-, O, ? 항목만 따로 모은 목록과 '점검하지 못한 것'.

## 금지
코드·설정·시험을 수정하지 않는다(보고서 파일만 쓴다). 비밀 값(환경 변수, 토큰, SSH 키, secrets/, .env, 웹훅)을 읽거나 출력하지 않는다. `env`/`printenv` 금지. sudo 금지. Artifact 금지. 다른 리포를 수정하지 않는다. 기한 상한을 임의로 만들지 않는다. 막혀도 포기하지 않고 보고한다.
