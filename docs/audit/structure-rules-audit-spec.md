# 구조 규칙 6개 전수 점검 기준서 (2026-10-28, D104)

사용자 지시: 아래 규칙은 프로젝트의 모든 요소에 적용된다. 하나하나 꼼꼼하게, 시간이 걸려도 전수 점검한다. 계약을 정확히 준수한다.

## 규칙
- R1 영역은 서로의 구조를 모른다.
- R2 영역은 작업의 단위인 컴포넌트를 가진다.
- R3 컴포넌트는 다른 컴포넌트와 독립적이며 서로의 구조를 모른다.
- R4 컴포넌트는 자신에게 할당된 입력/출력 스키마와 자신의 업무밖에 알지 못한다.
- R5 영역은 자기 컴포넌트 사이의 스키마를 알고 그 스키마를 책임진다(컴포넌트들이 교류할 수 있게).
- R6 영역 사이의 스키마는 헤드가 책임진다.
- R7(D104, ADR 0010) 컴포넌트가 내보낸 값은 보증된 값이다. 다른 컴포넌트는 그 값을 믿고 쓴다(재검증·재시도·같은 규칙의 재구현을 하지 않는다). 영역 바깥의 믿을 수 없는 입력(환자 입력, 외부 요청)을 경계에서 검증하는 것은 해당하지 않는다.

## 점검 항목(영역마다 전부)
A. 컴포넌트 목록: 이 영역의 모든 컴포넌트(작업 단위). 이름, 파일, 할당된 입력 스키마, 출력 스키마, 업무 한 줄. 어느 컴포넌트에도 속하지 않는 코드(접착 코드)는 별도 목록. 컴포넌트 경계가 없는 덩어리는 그렇다고 쓴다.
B. R3·R4: 컴포넌트가 다른 컴포넌트의 모듈·내부 함수·내부 상태·설정 필드를 직접 쓰는가. 하나의 함수가 두 컴포넌트의 일을 `role`·종류 분기로 같이 하는가. 전역 상태 공유. 자기 I/O 스키마 밖의 정보(이웃 컴포넌트의 형식, 저장 구조)에 기대는가.
C. R5: 영역 안 컴포넌트 사이 스키마가 기계가 읽는 형태(JSON Schema, 타입 있는 데이터클래스, Protocol 등)로 한 곳에 정의돼 있는가. 정의 위치. 없거나 암묵적(딕셔너리 키 관습)인 곳.
D. R1: 이웃 영역의 구조에 기대는 곳: 이웃 패키지 import(코드 의존), 이웃 폴더 경로(`../x`), 이웃 설정 키 목록·Dockerfile 인자·API 응답의 계약 밖 모양, 이웃 환경 변수 이름, 이웃 포트·호스트. 허용: boundary-contracts의 스키마·클라이언트·검증기(계약), 워크스페이스 규칙이 허용한 읽기 전용 참조(`../survey-service/schema`, `../boundary-contracts`, `../head/shared/areas.json`).
E. R6: 이 영역이 제공·소비하는 영역 간 인터페이스마다 boundary-contracts에 스키마가 있는가. 영역 간에 오가는데 계약에 없는 형식(잡 설정, 빌드 인터페이스, 파일 형식 등)은 모두 나열. 영역 안에서 정의됐지만 영역 경계를 넘는 스키마도 나열.
F. 계약 준수: 제공·소비하는 각 인터페이스를 `boundary-contracts`의 문서(INTERFACES.md, HTTP.md, PUBLIC_API.md 등)와 스키마에 비춰 구현을 대조한다. 상태 코드, 필드, 오류, 헤더, 멱등, 타임아웃 값. 어긋남은 계약 절 번호와 코드 파일:줄을 함께 적는다. 계약 패키지의 적합성(conformance) 시험이 있으면 돌린다.
G. R7: 같은 규칙을 이웃 컴포넌트와 이중으로 검증·재시도·재구현하는 곳.

## 증거 규칙
- 모든 발견에 `파일:줄`과 코드 인용(2줄 이내)을 붙인다. 읽지 못한 것은 읽지 못했다고 쓴다. 추측하지 않는다.
- 발견 형식: ID(영역약자-번호), 규칙(R1~R7), 심각도(P1 독립성을 깨고 실제 결합을 만든다 / P2 숨은 결합·암묵 스키마 / P3 정리 수준), 위치, 인용, 왜 위반인가, 최소 수정 방향.
- "문제없음" 항목도 무엇을 어떻게 확인했는지 적는다(검색한 패턴, 읽은 파일 목록). 확인 범위가 보이도록.
- 읽지 못한 파일, 시간 때문에 못 본 부분은 별도 절 "점검하지 못한 것"에 적는다.

## 금지
- 코드·설정·테스트를 수정하지 않는다(점검 보고서 파일만 쓴다). 비밀 값(환경 변수, 토큰, SSH 키, `secrets/`, `.env`, 웹훅)을 읽거나 출력하지 않는다. `env`/`printenv` 금지. sudo 금지. Artifact 금지. 다른 리포를 수정하지 않는다.
