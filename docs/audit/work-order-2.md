# 작업 지시서 2 (2026-10-28, D104) — 지시서 1을 대체하는 전체 동시 투입

지시서 1(`work-order-1.md`)의 A(결함 수정)·B(경계 형식 스키마 초안 변경 요청)를 그대로 수행한다. 아래는 그 위에 더하는 규칙이다. 이 작업은 **멈추지 않고 끝까지** 한다. 헤드도 멈추지 않는다.

## 작업 규칙 (지시서 1에 더함)
1. **작업 브랜치**: 시작하자마자 자기 리포에서 `git switch -c wo2`(없으면 만든다). 모든 커밋은 `wo2`에만. `main`은 건드리지 않는다. 끝날 때 작업 트리를 깨끗하게 둔다. 헤드가 `wo2`를 검증하고 병합한다.
2. **이전 시도는 참고만**: 일부 리포에는 이전에 중단된 시도가 `wip/work-order-1` 브랜치(synthetic-data, release-gate, ops-feedback, deploy)나 `git stash list`(survey-service, question-authoring, admin-console)에 있다. 읽어서 출발점으로 삼아도 되지만 그 안의 시험과 결과를 통과 근거로 삼지 않는다. 필요한 것은 직접 다시 확인한다.
3. **통과 근거는 독립 출처**: 고치는 사람이 쓴 시험만으로는 근거가 되지 않는다. 계약 문서(`../boundary-contracts`)의 규칙, 계약 패키지의 적합성 시험(`conformance`), 계약의 검증기(`boundary_contracts.validator`)에서 나온 기대값으로 확인한다. 보고에는 **헤드가 그대로 복사해 돌려 볼 수 있는 재현 명령**(고치기 전 실패, 고친 뒤 통과)을 적는다.
4. 통과 개수는 실제 출력의 숫자만 적는다.
5. 데모에 필요한 항목(영역 지시의 "데모" 표시)을 가장 먼저 한다.

## 데모 요구 (사용자 지시)
- 데모는 `scripts/demo.sh up`으로 뜨고, 모델 서빙 자리의 **LoRA-A, LoRA-B 컴포넌트만** 모방 컴포넌트로 바뀌고 나머지는 진짜 코드다.
- LoRA-A 모방은 입력 발화와 현재 문항에 따라 **다양한 종류의 출력**(값 채우기, 재질문, 확인, 정정, 건너뛰기, 보류, 다음 문항 이동, 종료)을 낸다. 결정적이어야 한다(같은 입력이면 같은 출력). 출력은 `ActionExtraction` 스키마를 지키고 turn-engine의 `validate_extraction`(의미 규칙)을 통과해야 한다. 의료 판단을 지어내지 않는다.
- LoRA-B 모방은 응답 요청의 재료에서 동작별로 **다양한 한국어 문장**을 낸다. 임상 조언을 지어내지 않는다.
- 키오스크 화면에 현재 대화(환자 발화와 시스템 응답)가 시간순으로 **보인다**. 브라우저 메모리에만 두고 저장하지 않는다(키오스크 원칙 유지).
- 키오스크가 해시(`#device=...`) 없이 데모 주소로 열린다(`/config.json` 경로, 기기 설정은 deploy가 데모 때만 내준다). 비밀 값은 대화·로그에 출력하지 않는다.
