# deploy 영역으로 넘김: 영역 사이 계약에서 걷어 낸 deploy 내부 사항 (2026-11-04, boundary-contracts 3.4.4 60dc386)

왜: 헤드가 영역 사이 계약(RUNTIME.md)에 deploy 영역 안 컴포넌트 사이의 구조를 적었다(구조 규칙 5·6 위반). 3.4.4 에서 걷어 냈다.
아래는 **deploy 가 자기 컴포넌트 계약(deploy 리포)에서 정할지 스스로 판단할 목록**이다. 헤드는 내부 구조를 정하지 않는다.
deploy 가 지켜야 하는 것은 RUNTIME.md 의 **출력**뿐이다(각 줄의 "영역 사이 출력").

| 옛 조항 | 걷어 낸 내부 내용(옛 문장 요지) | 영역 사이 출력(3.4.4) |
|---|---|---|
| R1.6 | doctor 의 시계 오차 점검, 감시 경보 | R1.6 NTP·어긋나면 R3.8/401 |
| R1.7 | 루트·중간 수명·교체 주기는 배포 ADR | R1.7 병행 신뢰·새 OUT-FILE |
| R2.1 | 헤더 선언 목록의 정본이 deploy RUNTIME-COMPONENTS | R2.1 계약 안의 헤더 목록 |
| R2.3·R5.2·R5.3 | 게이트웨이 자신의 /healthz·/readyz 본문·코드, 상류 준비 뒤 받기 | (없음) |
| R2.4 | 중계의 유휴 읽기 한도 > ping, 쌓지 않음 | R2.4 이벤트 즉시 도착·ping 15초 동안 끊기지 않음 |

| R8.2 | 경보 목록(발급 실패·수명 1/3·디스크 80%·readyz·시계), 로그 크기 상한 | (없음) |

deploy 의 기존 구현·시험(사이드카·인증서 갱신·경보 규칙 등)을 지우라는 뜻이 아니다. 그것들의 근거 문서가 영역 사이 계약이 아니라 deploy 자기 컴포넌트 계약이어야 한다는 뜻이다. 커밋 메시지·대응표가 폐지된 번호(R2.3·R4.2·R4.4·R4.5·R5.2·R5.3·R8.2·R10.7·R10.10)를 참조하면 deploy 자기 문서 번호로 바꾼다.
