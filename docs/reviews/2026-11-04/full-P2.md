## 판정 기준과 읽은 범위
- 맞음 = 칸의 출력이 현행 조항과 같고 출력하는 쪽·받는 쪽이 CONVENTIONS 13절과 맞다. 낡음 = 칸이 3.4.4 이전 기준(열림 표시, 해소된 모순, deploy→platform, 사라진 조항)이라 칸 갱신이 필요하다(계약 문장은 맞음). 모순 = 계약 문장끼리 어긋난다. 계약 빈칸 = 현행 계약에 출력이 없다(이번 몫에서는 0).
- 읽음(전문): RUNTIME.md 전체(R1~R10 현행, 커밋 1bbf6dd), CONVENTIONS.md 3·4·6·9·13절, HTTP.md I5·I6 전문, RUNTIME-MATRIX-CELLS.md 머리말과 "묶음 3" 표 180행 전부(476~660행), PUBLIC_API.md 재시도 규칙·429·408/413 행(grep 줄, 전문은 아님), schemas 의 `RollbackRequest`·`RollbackReceipt`·`IngestResult`·`OpsFeedbackJobResult`·`GateJobResult`·`SyntheticJobResult`·`SurveyPurgeOutput` 설명, boundary_contracts/clients/_http.py 의 `_STATUS_CODE`·`_TRANSPORT_LIMIT`·`_map_error`(349~372행).
- 읽기 전용으로 확인한 영역 코드: release-gate `link_http_server.py` 131·164행(승인 201/200, 제출은 항상 202), `pointer_control.py` 58행(이미 활성이면 현재 포인터를 돌려줌). 시험은 실행하지 않았다.
- 읽지 않음: PUBLIC_API.md 전문과 INTERFACES.md 전문(칸이 인용한 I5~I7 문장만 확인), EXTERNAL_SCHEMAS.json, 문진 스키마. 칸 안의 PUBLIC_API "○○행" 번호는 3.4.4 에서 줄이 밀렸을 수 있으나 문장 내용으로 대조했다.
- C24: 여섯 칸 모두 호출 칸에 "영역 내부로 뺌" 표시가 있음을 확인했다(CONVENTIONS 13절 "데이터베이스는 영역의 컴포넌트다"와 일치). 내용 판정은 하지 않았다(지시).

## 계약 문장을 고쳐야 하는 것 (모순 1건, 계약 빈칸 0건)

### K1. RUNTIME.md R10.8 과 HTTP.md I5 의 어긋남 (C09 F20)
- 두 문장: HTTP.md I5 `activate` "이미 활성인 같은 `release_id` 면 200 으로 현재 포인터를 그대로 돌려준다(…, RUNTIME R10.8)" — 그런데 R10.8 본문에는 활성화 문장이 없다. 그리고 R10.8 "후보 제출(I5): 같은 대상(문진표들·LoRA-A·LoRA-B)이면 기존 접수를 200 으로 돌려준다(새 접수는 202)" vs HTTP.md I5 `submit_candidate` 응답 "`GateSubmission` (202)"와 INTERFACES.md I5 "같은 subject의 중복 요청은 기존 접수를 돌려준다".
- 확인한 것: release-gate `link_http_server.py` 164행은 제출에 항상 `Response(202, …)` 를 낸다(코드를 읽음, 실행은 안 함). R10.8 의 "200"은 이 구현과 HTTP.md 에 없다. 활성화는 `pointer_control.py` 58행이 이미 활성이면 현재 포인터를 돌려준다(HTTP.md 와 같음).
- 고칠 문장(RUNTIME R10.8 출력 열): ① 추가: "활성화(I5): 이미 활성인 같은 `release_id` 면 200 으로 현재 포인터를 그대로 돌려준다(새 포인터·버전을 만들지 않는다)." ② 후보 제출 문장 교체: "후보 제출(I5): 같은 대상(문진표들·LoRA-A·LoRA-B)이면 기존 접수를 그대로 돌려준다(상태 코드는 새 접수와 같은 202)."
- 근거: 기존 설계·시험과 같게(구현이 항상 202; R10 머리의 "기존 설계·시험과 같게" 원칙), RFC 9110 9.2.2(재전송의 효과가 한 번과 같으면 충분하고 상태 코드까지 같아야 하는 것은 아니다), CONVENTIONS 4절 "POST 의 멱등은 이 절의 규칙이다".
