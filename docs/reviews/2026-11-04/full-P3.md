## 결함 목록 (10칸, 5건)

**D1 (모순, C15 F21·F27). 환자 턴 중 저장소 장애가 503 인지 200 NOT_COMMITTED 인지.**
- 두 문장: RUNTIME R3.10 "쓰기 불가(디스크 가득 포함)… 503 {"code":"UNAVAILABLE"}" / PUBLIC_API 35행 "`write_committed`(기록이 저장됐는지: COMMITTED/NOT_COMMITTED)", 31행 "확정되지 못한 턴(NOT_COMMITTED)은 … 같은 turn_id 재전송이 다시 처리된다", R3.20 은 턴 마감만 200 NOT_COMMITTED 로 정한다.
- 고칠 문장(제안, 헤드가 survey-service 의 두 경로 중 정본을 정해야 한다): RUNTIME 에 새 행 `| R3.28 | 환자 턴 처리 중 받는 서비스의 저장소가 멈춤·쓰기 불가(R3.10 입력) | 503 {"code":"UNAVAILABLE"}(R3.10). 200 NOT_COMMITTED 는 R3.20(턴 마감)과 모델 단계 실패처럼 서비스가 응답을 만든 경우뿐이다. 키오스크는 둘 다 같은 turn_id 로 재시도한다(PUBLIC_API) |`, PUBLIC_API 35행에 "저장소 장애는 503 이고 이 값은 응답을 만든 턴에서만 쓴다" 한 줄. 근거: R3.10 의 일반 규칙, RFC 9110 15.6.4. 확인 한계: 코드에 `orchestrator.py` 의 StoreError -> 503 과 `turn_graph.py n_fail_no_session` -> NOT_COMMITTED 가 함께 있다(어느 입력에 어느 경로가 쓰이는지는 읽지 않음).

**D2 (모순, C16 F24·C17 F24). R3.25 가 SSE 끊김까지 덮는다.**
- 두 문장: R3.25 "응답 헤더를 보낸 뒤 본문을 다 보내기 전에 연결이 끊김 -> OUT-NET(브라우저는 오류 안내)" / PUBLIC_API 54행 "연결이 닫히면(readyState CLOSED) 지수 백오프로 새로 연결"·44행 "끊기면 Last-Event-ID 로 이어 받는다 … resync".
- 고칠 문장: R3.25 입력 끝에 "단 OUT-STREAM(text/event-stream)은 제외한다. 스트림이 끊기면 출력은 R2.4 와 PUBLIC_API 의 SSE 규칙(지수 백오프 재연결, Last-Event-ID, resync)이다". 근거: WHATWG HTML SSE.

**D3 (계약 빈칸, C36 F23·F27). OUT-FILE 의 출력 주체가 CONVENTIONS 13절 예외 열거에 없다.**
- 두 문장: RUNTIME R1.5 "deploy(배치 도구, 배포 때) -> compose 밖 호출자" 가 이름→주소 표·SHA-256 목록을 내보낸다 / CONVENTIONS 13절 "유일한 예외" 열거는 환경 변수·비밀 파일·루트 인증서(SSL_CERT_FILE)·이미지 빌드·게시 호출·JobsDeclaration·Exposure·SetupEnvReport·서비스 기동·잡 실행만 든다.
- 고칠 문장: CONVENTIONS 13절 "유일한 예외" 열거에 "compose 밖 호출자에게 내보내는 이름→주소 표와 두 파일의 SHA-256 목록(RUNTIME R1.5, OUT-FILE)"을 넣는다. 근거: 구조 규칙 6 의 예외는 열거되어야 한다.

**D4 (낡음, C23 F23·F25). 푸시 칸이 R3.18 현행보다 좁고 근거 없는 문장을 가진다.** F23 의 "푸시는 자동으로 두 번 나가지 않는다"를 정하는 조항이 없다. 갱신 문장은 표의 '고칠 것' 열에 있다.

**D5 (낡음, C24 F22·C30 F26). 소관 표기.** C24 F22 는 이전 R10.1(DB 와 감시를 묶어 R1.1~R1.3 적용)을 인용한다: 현행 R10.1 은 DB 를 영역 컴포넌트로 보고 R3.10 만 정한다. C30 F26 은 감시를 deploy 소관으로 적었으나 감시는 platform 이다. (칸 수: C24 F22, C30 F26. D4 와 합쳐 낡음 4칸.)

## 확인 못 한 것 / 한계
- 칸의 '입력'(2열)은 대조 대상이 아니라 출력·조항만 대조했다(입력은 호출 × 실패 정의 그대로).
- C24 행 7칸은 지시대로 '영역 내부' 표시(칸 호출 열의 "3.4.4 영역 내부로 뺌")만 확인했고 그 칸의 출력은 R3.10 과 대조해 맞음으로 두었다(C24 F22 는 위 D5).
- survey-service 의 푸시 발송 코드(Topic 사용 여부)는 읽지 않았다.
- 같은 문장이 호출마다 반복되는 칸(C01~C22 의 F21~F27 다수)은 같은 조항으로 한 번씩 대조하고 칸마다 조항을 적었다(복사한 것이 아니라 호출 종류별 조항 매핑을 적용했다: 사람 경로 / 키오스크 / 직원·의사 / 서비스 사이 / 개별 호출).
